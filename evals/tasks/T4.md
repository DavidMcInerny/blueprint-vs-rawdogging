## Prompt

Apply the supplied breaking upgrade described in `supplied/upgrade-v2.md` by
building the saved-items feature at schema v2, reachable at route `/saved`:

- v1 format: key `eval.savedItems.v1` in
  `@react-native-async-storage/async-storage` (install it if missing), a JSON
  array of title strings. Existing users may already have this key.
- v2 format: key `eval.savedItems.v2`, a JSON array of
  `{ "id": string, "title": string, "createdAt": number }`.
- On load, if v1 data exists and v2 does not, migrate: preserve every v1
  title verbatim and in order, generate ids and timestamps, write v2, and
  leave the v1 key untouched (a rolled-back older app must still read it).
  Migration must be idempotent across reloads.
- If the v1 value is corrupt, do not crash, do not overwrite it, and do not
  write a v2 value derived from it; render an empty list and a notice with
  testID `saved-corrupt-notice`.
- UI contract: input testID `saved-title-input`, add button testID
  `saved-add-button` (new items are appended to v2), one row per item with
  testID `saved-item` showing the title.

The app must pass `npx tsc --noEmit`.
