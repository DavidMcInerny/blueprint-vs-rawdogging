## Ranking rule and consumer commitment

Order favours demonstrated repeated behaviour and an existing small boundary, then protection of real user work, then more speculative interaction/product expansion. Rank is the order to revisit if a product requests the case; it does not authorize implementation.

The reports establish two-domain adoption of drafts/import-review and selected shell/workflow behaviour. They establish Golf's inbox and OddsBasket's settings/upload surfaces. They do **not** establish a committed second product requirement for cross-tab leases, guest claims, collaboration, OCR review, favourites or planning. A named next consumer below is a concrete candidate to ask when that workflow is commissioned; “uncommitted” is deliberate. No new extraction issue is promoted from this triage. Existing equivalents stay retained; new source is deferred until a repeated need is established.

Dispositions mean: **retain existing** uses the canonical behaviour; **compare** reads the selected donor/host loop against it before changing source; **recipe** keeps composition and policy product-owned; **defer** records missing demand/contracts; **exclude** prevents domain/provider/data copying. Each acceptance case applies only if that candidate is later selected.

## Acceptance contract before any later implementation claim

A promoted candidate needs a named consumer owner and concrete repeated job, the relevant pinned donor source plus nearby tests, a selected existing equivalent, and one bounded change/recipe with its host adapters. Record a real need rather than interpreting a second product's name as commitment. If the two products differ fundamentally, retain their recipes/providers rather than inventing switches to force reuse.

For identity/sync claims specifically, completion evidence must include distinct-account isolation, A → B → A/stale-work fencing, the actual durable/atomic storage boundary and actual server authorization wherever protected remote state is involved. Native/provider behaviour needs the selected platform/provider evidence under #9. Pure controller fakes, component rendering, compile success and a local lease callback do not establish these guarantees. These are criteria for a feature that is selected, not additional work required to finish this triage or unrelated consumer delivery.

Preserve domain rules, scoring/handicaps, course matching, coaching content, map/geospatial calculations, booking/pricing/capacity policy, catalog datasets, licensed artwork, branding, credentials and provider configuration outside shared source. Native widgets, OCR/voice engines, games, backend migrations and course publishing stay excluded from this queue's implementation scope; they require a separately requested product case and relevant rights/platform review. Reusing generic import/review or device ports does not grant those rights or implement those engines.
